The key idea · read this first

Every search is the same loop

BFS, DFS, UCS, Greedy and A* all run the loop below. Only line 4 changes: which waiting path you take out of the fringe. Learn the loop once and every algorithm becomes one sentence.

1fringe = [ start ]
2repeat:
3 if fringe is empty: return FAILURE
4 path = take ONE path out of fringe # the only line that changes
5 if path ends at the goal: return path
6 (graph search) if its state was expanded before: skip it, else add it to the closed set
7 for each child of that state: add path + child to fringe

  2. Press Restart, switch to DFS. Same graph, same loop, different order.
  3. Switch to UCS, then A*. Now each fringe entry carries a number and the list stays sorted by it.
The fringe holds paths, not nodes

Each entry is a whole route from the start, like S-B-C. That is why the same state can sit in the fringe twice: two different ways of reaching it. The goal test looks at the last state of the path.

Generate vs expand

Expanding a path means taking it out and making its children (line 7). Making a child is generating it. A path can be generated long before it is expanded, or never expanded at all.

Glossary · plain English

The words, without the jargon

The slides use these without explaining them. Each one is a single idea.

State

One situation the problem can be in. On a graph, a node: S, A, G.

Start and goal

Where you begin, and the state you are trying to reach. The goal test checks whether a state is the goal.

Successors (children)

The states you can reach in one move. Written in alphabetical order unless the paper says otherwise.

Path cost g(n)backward cost

What you have paid so far: the sum of edge costs from the start to n along this path.

Heuristic h(n)forward cost, estimate

A guess of the cost still left from n to the goal. Given on the graph as h = …

f(n) = g(n) + h(n)

Paid so far plus estimate still to go: the estimated total cost of a solution through n. A* sorts by it.

Fringefrontier, open list

The waiting list of paths generated but not yet expanded. The data structure decides the algorithm.

Expand

Take a path out of the fringe and generate all its children.

Closed setvisited, explored

The states already expanded. Only graph search keeps one. Tree search remembers nothing.

Search tree

The drawing of every path the algorithm generated. The same state can appear many times in it.

Complete

If a solution exists, the algorithm is guaranteed to find one.

Optimal

The solution it returns is guaranteed to be the cheapest one.

b, d (or s), m

b: branching factor, the most children a node has. d or s: depth of the shallowest goal. m: maximum depth of the tree.

C* and ε

C*: cost of the cheapest solution. ε: the smallest edge cost. UCS’s time is O(bC*/ε).

Admissible

h never overestimates: h(n) ≤ the true cheapest cost from n to the goal.

Consistent

On every edge u → v: h(u) − h(v) ≤ cost(u, v). The estimate never drops faster than the real cost.

ThresholdIDA*

The f limit for one IDA* iteration. Nodes with f above it are cut off.

Best, Alt, f_limitRBFS

Best: the child with the lowest f. Alt: the second lowest. f_limit: how high f may go before this call gives up.

Rational, in one line (slide 4)

A system is rational if it does the “right thing” given what it knows: it maximises expected utility. It is judged only by the decisions it makes, not by the thought process behind them.

The Turing test (slides 7–8)

Alan Turing, 1950. A computer passes if a human interrogator, asking written questions, cannot tell whether the answers come from a person or a computer. It needs natural language processing, knowledge representation, automated reasoning, machine learning. The total Turing test adds computer vision and robotics.

Agents · deck 02, slides 16–19

Good behaviour: rationality

A rational agent does the right thing, and “right” depends on how you measure success. Choose the performance measure carefully: it shapes the behaviour you get.

Definition, word for word

For each possible percept sequence, a rational agent should select an action that is expected to maximise its performance measure, given the evidence provided by the percept sequence and whatever built-in knowledge the agent has.

Rationality depends on four things (slide 18)

1 · Measure

The performance measure that defines success.

2 · Knowledge

The agent’s prior knowledge of the environment.

3 · Actions

The actions the agent can perform.

4 · Percepts

The percept sequence so far.

MNEMONICwhat counts, what it knows, what it can do, what it has seen.

Rational

Maximises expected performance. Decides well with what it knows, and can still be unlucky.

Omniscient

Knows the actual outcome before acting. Impossible in practice, and rationality does not require it (slide 19).

Measuring the vacuum (slides 16–17)

Dirt cleaned in an 8-hour shift, or a point per clean square per step minus electricity and noise? The same average can come from steady work or bursts with breaks. You choose the measure, and it shapes the behaviour.

EXAM USEIf an agent made a bad move because of bad luck, it can still be rational: it chose the action with the best expected result given its percepts.

Agents to search · uninformed deck, slides 1–5

Formulating a search problem

A search problem has a state space, a successor function (actions with costs), a start state and a goal test. A solution is a sequence of actions that takes the start state to a goal state. Asked as “formulate as a search problem” in all three midterms.

Template: one line each
  1. States: what changes during the search. Include any resource that matters, such as battery.
  2. Initial state: the starting values.
  3. Actions: what the agent may do, with restrictions (only unblocked corridors).
  4. Transition model: the new state after each action.
  5. Goal test: a condition on the state.
  6. Path cost: the price of each action.
Romania (slide 3)

States: cities. Actions: drive to an adjacent city, cost = distance. Start: Arad. Goal test: is it Bucharest?

Arad → Sibiu → Rimnicu Vilcea → Pitesti → Bucharest = 140 + 80 + 97 + 101 = 418. Via Fagaras: 140 + 99 + 211 = 450. Both are solutions; they differ in cost.

World state vs search state (slide 5)

The world state has every detail. The search state keeps only what planning needs. Pathing: (x, y). Eat-all-dots: (x, y) plus a true/false for every dot, because the goal depends on the dots.

Worked: the hospital robot (Fall 2025 Q1b, slide 24)

StatesAll possible robot locations together with the remaining battery.
Initial stateRobot at the pharmacy with a full battery.
Goal testMedicine delivered at the specified patient room.
ActionsMove to an adjacent unblocked corridor (up, down, left, right).
Transition modelThe location changes after each move, and one unit of battery is used.
Path costEach move costs 1 battery unit.

WHYThe battery is limited and every move uses one unit, so the battery belongs in the state. Blocked corridors are handled by the actions.

Uninformed · slides 32–35 of the informed deck

Tree search vs graph search

You asked how tree search works without marking visited nodes. It simply does not remember anything, so it can expand the same state again and again. Graph search adds exactly one thing: a memory of what it has already expanded.

Learn it firstabout 3 minutes
1

The problem: going in circles

Tree search never remembers where it has been. If A leads to B and B leads back to A, it will happily expand A, then B, then A again. It wastes time, and with DFS it can loop forever.

2

The fix: a closed set (a "visited" list)

Graph search keeps a list of states it has already expanded. When it takes a path out of the fringe whose last state is already on that list, it throws it away (skips it) without expanding.

3

Same algorithm, one extra rule

BFS, DFS, UCS, A*: each one has a tree version and a graph version. The fringe rule stays the same. Graph search just adds: "if the state is closed, skip; otherwise add it to closed and expand."

4

The catch

Skipping is only safe if the first time you expanded a state you got there the cheapest way. For UCS that is always true. For A* it needs a consistent heuristic, which is exactly the Fall 2025 Q3 trap (cost 6 in tree search, 7 in graph search).

In one line

Graph search = tree search + "never expand the same state twice".

Don't confuse

A state goes into closed when it is expanded (taken out), not when it is added to the fringe.

Check yourself
BFS graph search on Fall 2025 Q2(a): what happens when S-A-C comes out?

C was already expanded (through S-C), so C is closed. S-A-C is skipped: not expanded, no children added.

Tree search
  • No memory. The same state can be expanded many times, once for each path that reaches it.
  • Still finds answers. It just does extra work.
  • We still never walk back along the current path (S-P-S-P…), or DFS would loop forever on an undirected graph.
Graph search = tree search + closed set
  • Before expanding a path, check its last state against the closed set. If it is there, skip the path.
  • Otherwise expand it and add the state to the closed set.
  • Every state is expanded at most once (slide 35). Children already in the closed set are not even added.
Try this

Run BFS to the end with Tree search and count the nodes in the search tree. Then switch to Graph search. Same answer, a much smaller tree, and dashed “skip” entries where a repeat was thrown away.

Does graph search ever hurt?

For BFS, DFS and UCS, no. For A* it can: with a heuristic that is admissible but not consistent, graph search can throw away the cheaper path to a state. That is Q3(b) of the Fall 2025 paper; see the A* page.

Uninformed · asked as “show the corresponding tree representation”

From a graph to its search tree

Papers often say: draw the tree representation of this graph, then apply DFS or UCS on it. The tree lists every path from the start. Build it one level at a time: each arrow out of a state becomes one child.

Learn it firstRead this before the visualiser · about 4 minutes
1

A graph is a map. A search tree is a diary of trips.

The state graph is the question paper's picture: each state (S, A, B…) appears once, with arrows and costs. A search tree records every route you could take from the start. Each tree node is a whole path, like S-A-B, not just a letter.

2

Why the same letter shows up many times

In Fall 2025 Q2(a) you can reach C three ways: S-C, S-A-C and S-A-B-C. On the map, C is one circle. In the tree, it is three different nodes, because they are three different trips with three different costs (10, 11 and 8).

3

How to draw it, every time

  1. Put the start at the top. Write g = 0 under it.
  2. For a node, look at its last letter on the map. Every arrow leaving that letter becomes a child.
  3. Draw the children left to right in alphabetical order.
  4. Under each child write g = the parent's g + the edge cost.
  5. Stop a branch when it reaches the goal, or (on an undirected map) when the next letter is already on that same branch.
4

What the search methods do with the tree

Every method walks this same tree. They only differ in which node they open next: BFS goes level by level, DFS dives down the left side, UCS takes the smallest g, A* the smallest g + h. Draw the tree once and you can answer all of them.

In one line

Graph = each state once. Tree = each path once.

Exam habit

Write the full path inside or beside each tree node (S-A-B). Then reading the answer later is copying, not thinking.

Check yourself
Can a search tree be infinite even when the graph is small?

Yes. If the graph has a cycle (A to B and B back to A), the paths A-B-A-B-… never end. That is why tree search can loop forever, and why graph search keeps a closed set.

Under S-A-B in Fall 2025 Q2(a), what children do you draw and what is their g?

B's arrows go to C (cost 2) and G (cost 5). S-A-B has g = 6, so S-A-B-C has g = 8 and S-A-B-G has g = 11.

Rules for drawing the tree
  1. The root is the start state, g = 0.
  2. For each node, draw one child per arrow leaving its state, alphabetical, left to right. Write the path cost g under each node (parent’s g + edge cost).
  3. Never repeat a state that is already on the same path (that would be a cycle).
  4. The goal is a leaf: do not grow it further.
  5. The same state can appear several times, once for each different path. That is normal.
Then apply the search

Every visualiser now has a Full search tree tab. It draws this whole tree first, then lights it up as the algorithm runs. The small numbers show the order of expansion, which is exactly what you write in the exam.

Why the exam asks for it

Search algorithms really work on the tree, not the graph: each fringe entry is one tree node, a whole path. Drawing the tree first makes the expansion order easy to see and easy to mark.

Uninformed · how to write the result from the stack or queue

Reading the answer from the fringe

You never need to go back to the graph to find the answer. Every fringe entry carries its whole path and its cost. When the goal entry comes out, everything you have to write is already in your stack or queue table.

1 · Expansion order

Go down the “taken out” column of your table and write the last state of each entry: S, A, B, … In graph search, leave out the entries you skipped as repeats.

2 · Solution path

The entry that held the goal is the path. If the goal came out as S-A-B-C-G, the path is S → A → B → C → G. Nothing to work out.

3 · Path cost

In UCS and A* you already wrote g next to every entry, so the goal’s g is the cost. In BFS and DFS, add the edge costs along that path.

Two ways to write a fringe entry

Whole path, as this guide does: S-A-B. The answer can be read straight off the goal entry.

Node with its parent, as some teachers prefer: B(A), meaning “B, reached from A”. Shorter to write, but at the end you trace back: G came from C, C from B, B from A, A from S. Read G ← C ← B ← A ← S, then reverse it. Both give the same answer.

Uninformed · fringe = queue

Breadth-first search

BFS spreads out in rings: every state one step away, then every state two steps away, and so on. A queue makes this happen automatically, because new paths wait at the back.

Learn it firstabout 4 minutes
1

The picture: ripples in water

Drop a stone at S. The first ring touches everything one step away, the next ring everything two steps away. BFS explores exactly like that: all paths of 1 edge, then all of 2 edges, then 3.

2

The tool: a queue (a line at a shop)

New paths join the back. The path taken out is always the one at the front, the one that has waited longest. Because short paths are added first, they are also taken out first. That is the whole trick.

4

What BFS is good and bad at

It finds the path with the fewest edges. It ignores costs. Here S-C-G has 2 edges but costs 11, while S-A-B-C-G has 4 edges and costs only 9. BFS is optimal only when every edge costs the same.

In one line

Queue. Shallowest first. Fewest edges, not cheapest.

Course rules

Children in alphabetical order. Stop when the goal is taken out, not when it is added.

Weak spot

Memory. It keeps a whole level in the queue: O(bd).

Check yourself
S-C-G was added to the queue in row 3. Why didn't BFS stop there?

The goal test happens when a path is taken out. S-C-G had to wait behind S-A-B and S-A-C, which were already in the queue.

When is BFS guaranteed to find the cheapest path?

When every edge has the same cost (step cost 1). Then fewest edges = cheapest.

Rules to write in the exam

  2. Take out the path at the front.
  3. If it ends at the goal, stop and return it.
  4. Otherwise add its children to the back, in alphabetical order.

Uninformed · fringe = stack

Depth-first search

DFS dives down one branch as far as it can, then backs up to the last fork and tries the next branch. A stack makes this happen: the newest path is always on top.

Learn it firstabout 4 minutes
1

The picture: a maze, one hand on the wall

DFS picks a direction and keeps going deeper until it hits a dead end, then backs up to the most recent choice it skipped. It finishes one branch before it looks at the next.

2

The tool: a stack (a pile of plates)

New paths go on top, and you always take from the top. So the newest path, the deepest one, is opened next. To make the alphabetically first child come out first, push children in reverse order (C, then B, then A).

3

4

Lucky, not clever

DFS found the cheapest path here only because the left branch happened to be good. It never compares costs. On another graph it can return a terrible path, or loop forever if there is a cycle.

In one line

Stack. Deepest first. Not optimal, not complete in tree search.

Strength

Memory: only the current branch and its siblings, O(b·m).

Don't confuse

BFS queue: take the oldest. DFS stack: take the newest.

Check yourself
Why push children in reverse alphabetical order?

The last thing pushed is on top. Pushing C, B, A leaves A on top, so A is opened first, matching the alphabetical tie rule.

S-A-B-G is a goal path and is in the stack. Why is it not the answer?

It sits under S-A-B-C, which is on top. DFS takes S-A-B-C first, and its child S-A-B-C-G goes on top and comes out before S-A-B-G.

Rules to write in the exam
  1. The fringe is a LIFO stack. Start with [S].
  2. Take out the path on top.
  3. If it ends at the goal, stop.
  4. Otherwise push its children in reverse alphabetical order (C, then B, then A), so the alphabetically first child ends up on top and comes out next.
Do heavier edges go first?

No. DFS never looks at edge costs. The order is alphabetical only. Costs matter only in UCS, A* and the algorithms built on them.

Depth-limited and iterative deepening

Depth-limited search is DFS that refuses to go deeper than a limit. Iterative deepening runs it again and again with limit 0, 1, 2, … until the goal turns up. You get BFS’s shallowest answer with DFS’s small memory.

1

Depth-limited search: DFS with a leash

Pick a limit L. Run DFS, but never expand a path that already has L edges. It can no longer dive forever, but if the goal is deeper than L it is missed.

2

Iterative deepening: try L = 0, 1, 2, …

We don't know the right limit, so try them all in order. Each round starts again from scratch at the start state. The first round that finds a goal gives the answer.

Bidirectional search

Run two searches at once: forward from the start and backward from the goal. Stop when they meet. Two small searches of depth d/2 replace one big search of depth d.

Learn it firstabout 3 minutes
1

Dig the tunnel from both ends

Run one search forward from the start and another backward from the goal, taking turns. Stop when the two meet at a common state. The answer is the forward half joined to the reversed backward half.

2

Why it is so much faster

Each side only has to go half the depth. Two searches of depth d/2 cost bd/2 + bd/2, far less than one search of depth d, bd. With b = 10 and d = 6: 2,000 instead of 1,000,000.

3

When you can't use it

You must know the goal state exactly (not just "any checkmate"), and you must be able to go backwards: find the predecessors of a state.

In one line

Two half-searches meet in the middle: 2·bd/2 instead of bd.

Steps (slide 39)
  1. Start two frontiers: forward {S}, backward {G}.
  2. Expand one level from each side in turn, tracking visited nodes.
  3. After each expansion, check whether some node M is in both visited sets.
  4. If so, stop: path = S to M (forward) + M to G (backward).
Key idea (slide 37)

It does not discover an unknown goal. The goal must be known; what is unknown is how to reach it. It searches for a connecting path.

Advantages (slide 38)
  • Faster than BFS, explores far fewer nodes
  • Shortest path guaranteed (with BFS on both sides)
  • Efficient for large state spaces
Limitations (slide 38)
  • The goal state must be explicitly known
  • Backward operators must exist
  • High memory: two frontiers and visited sets
  • Hard with one-way actions and large branching

Heuristics: a guess of the distance left

A heuristic h(n) estimates how far state n is from the goal (slide 8). Uninformed search spreads out in every direction. With a good guess, search can head towards the goal instead.

Learn it firstStart here if "heuristic" means nothing yet · about 6 minutes
1

What a heuristic is, in plain words

You are driving to a city and come to a fork. You don't know the real road distance from each turn, but you can look at a map and see that one road points roughly towards the city and is about 40 km away as the crow flies. That quick guess is a heuristic.

In search, a heuristic is a number h(n) written next to each state: a cheap guess of how much it will still cost to get from n to the goal. In exam graphs it is the "h = 6" beside each circle.

2

g and h: behind you and ahead of you

g(n)cost already paid from the start to n. Exact, you add up the edges.
h(n)guessed cost still left from n to the goal. Given in the question, never calculated by you.
f(n) = g + hguessed total cost of a trip through n. A* uses this.

The goal always has h = 0: nothing is left to pay.

3

Why bother

BFS and UCS have no idea where the goal is, so they spread out in every direction. A heuristic is a sense of direction: Greedy and A* open the states that look closer first, and usually reach the goal after opening far fewer nodes.

4

A good guess never overestimates: admissible

Let h*(n) be the true cheapest cost from n to the goal. h is admissible if h(n) ≤ h*(n) for every state: it may be too hopeful, never too pessimistic. Example, Spring 2026 Q3:

StateSABCDG
h (given)851210
h* (true, worked out)963310
h ≤ h*?yesyesyesyesyesyes

To find h*, work backwards from G: D reaches G for 1, C reaches D for 2 so C costs 3, and so on. Every row is "yes", so h is admissible.

5

A stricter rule, checked on each edge: consistent

For every edge u → v: h(u) − h(v) ≤ cost(u, v). In words: walking one edge may not make the guess drop by more than you paid for that edge. Spring 2026, edge A → C: 5 − 2 = 3 ≤ 3, fine. Check all edges; one failure makes h inconsistent.

Consistent always implies admissible, not the other way round. Fall 2025 Q3 is admissible but fails at A → B (4 − 1 = 3 > 1).

In one line

Why it matters

Admissible ⇒ A* tree search is optimal. Consistent ⇒ A* graph search is optimal.

Exam answer shape

Check yourself
Is h = 0 for every state admissible? Is it useful?

Admissible, yes: 0 never overestimates. Useless: it gives no direction, and A* with h = 0 is just UCS.

You compute h*(D) = 4 but the question says h(D) = 6. What can you say?

h overestimates at D, so h is not admissible (and therefore not consistent either). That is the teacher's A* example.

Is h the cost from the start?

No, that is g. h always looks forward, from n to the goal.

Admissible (slide 21)

0 ≤ h(n) ≤ h*(n)

h*(n) is the true cheapest cost from n to the goal. Admissible means never overestimate. Optimistic guesses are safe: they may slow search down, but never hide the best path.

Consistent (slide 37)

h(u) − h(v) ≤ cost(u, v)

Checked on every edge. The guess may not drop by more than the edge actually costs. Then f never decreases along a path. Consistent always implies admissible.

Check any exam graph

Pick a graph. The checker finds the true cost h* from every node, then tests both conditions. The Fall 2025 graph is admissible but not consistent, and that is exactly what its Q3(b) asks about.

Making a heuristic: the 8-puzzle (slides 24–29)

Admissible heuristics usually come from a relaxed problem: drop a rule and solve the easier version exactly. Let tiles jump anywhere and you get h1, tiles misplaced. Let tiles slide through each other and you get h2, total Manhattan distance. Move tiles and watch both.

Dominance (slide 29)

h2 ≥ h1 for every state, so h2 dominates h1. Both are admissible, and the bigger one is closer to the truth, so A* expands fewer nodes: for 12-step solutions, 227 nodes with h1 and only 73 with h2 (slides 25–26).

The two ends (slide 29)

h = 0 is admissible but useless: A* becomes UCS. The exact cost h* is perfect but as hard as solving the problem. The max of two admissible heuristics is admissible too.

RBFS: recursive best-first search

RBFS behaves like A*, but keeps only the current path and its siblings in memory. When the branch it is in gets more expensive than the best alternative, it backs out and writes one number on the parent: how good that branch turned out to be.

Learn it firstabout 6 minutes
1

The idea: go deep, but keep a backup plan

RBFS dives down the best-looking branch like DFS, but at every level it remembers the f value of the second-best option (the alternative). If the current branch gets worse than that, it gives up on it and switches.

2

Three numbers at every node

bestthe child with the lowest f: go into it.
altthe second-lowest f among the children.
f_limitmin(alt, the limit passed down from above). Go into best only while its f ≤ f_limit.
3

Giving up remembers what it learned

When a branch is abandoned, its f is backed up: replaced by the best f found under it. That way, if RBFS comes back later, it knows how much that branch really costs. Children also take f = max(g + h, parent's f).

Rules to write in the exam, one recursive call

  4. Otherwise recurse into Best with f_limit = min(f_limit, Alt.f).
  5. When that returns a failure, Best gets its new f. Re-sort and repeat from step 2.
  6. Success when the goal is chosen as Best within the limit.

Local search · beyond classical search

When the path doesn’t matter

In 8-queens nobody asks for the moves, only for the final board. Local search keeps one current state and keeps improving it, instead of remembering paths.

Learn it firstabout 5 minutes
1

Two kinds of problem

In route finding the answer is the path (S-A-C-G). In 8-queens, timetabling or chip layout, the answer is just a good final state; how you reached it is irrelevant. For these, keeping a fringe of paths is wasted memory.

2

The idea: improve one state, step by step

Start with a complete (probably bad) state, for example 8 queens placed anywhere. Look at the neighbours: states one small change away. Move to a better one. Repeat. Memory stays tiny, and it works even when the state space is huge or infinite.

3

Optimisation: a number to push up or down

Each state gets a score: an objective function to maximise (profit, height) or a cost to minimise (for 8-queens, h = number of pairs of queens attacking each other). The goal is the best score, not a goal test.

4

Picture it as a landscape

Lay the states along the ground and make the height the score. Local search is a hiker in thick fog: they can only feel the ground right next to them. The landscape below has the shapes every exam names:

global maximumthe highest point anywhere: the true best state.
local maximumhigher than all its neighbours, lower than the global maximum. Hill climbing gets stuck here.
plateaua flat area: every neighbour has the same score, so there is no direction to go.
shouldera plateau that still rises on one side, so progress is possible.
ridgea sequence of local maxima that is hard to climb with single moves.
In one line

Keep one state, move to better neighbours, care only about the final state.

Two big wins

Constant memory. Works on huge or continuous state spaces where systematic search is hopeless.

The price

Not complete and not optimal: it can stop at a local maximum.

State: 8 queens, one per column. Neighbours: move one queen within its column (8 × 7 = 56 neighbours). Cost: h = pairs of queens that attack each other. Goal: h = 0.

Where it is used

Timetabling, scheduling, circuit layout, travelling salesperson tours, training the weights of a neural network: anywhere the final configuration is what counts.

Local search · steepest ascent

Hill climbing

Look at every neighbour, move to the best one, stop when none is better. The simplest local search, and the one every variant tries to fix.

Learn it firstabout 5 minutes
1

The whole algorithm

  1. current = a starting state.
  2. Look at all neighbours of current; pick the best one.
  3. If it is not better than current, stop and return current.
  4. Otherwise move there and go back to step 2.

That is steepest-ascent hill climbing: always the steepest step uphill. When the score is a cost like h, “uphill” means “h goes down”.

2

Do one step on 8-queens

On the board below, each empty square shows the h you would get by moving that column’s queen there. The board has h = 17. The smallest number on the board is the move hill climbing makes. Press Hill-climb one step and watch h fall.

3

Why it gets stuck

It stops at the first state with no better neighbour. That can be a local maximum (a small hill), a plateau (flat, no direction) or a ridge. From random 8-queens boards it solves only about 14% and gets stuck in 86%, but it is fast: about 4 steps when it succeeds, 3 when it gets stuck.

4

The fixes

VariantWhat changes
Sideways movesAllow moves to an equal neighbour (with a limit, e.g. 100) to cross plateaus. 8-queens: 14% → 94% solved.
StochasticPick randomly among the uphill moves, steeper ones more likely.
First-choiceGenerate neighbours at random and take the first better one. Good when there are thousands of neighbours.
Random restartIf stuck, start again from a new random state. If one run succeeds with probability p, expect about 1/p runs.
In one line

Greedy local search: best neighbour, until no neighbour is better.

Also called

Greedy local search. It never looks back and never plans ahead.

Complete?

No, it can get stuck. Random-restart hill climbing is complete with probability approaching 1.

Check yourself
A hill climber is on a plateau. What does plain steepest ascent do?

It stops: no neighbour is strictly better. With sideways moves allowed it could keep walking along the plateau.

Random restart succeeds 14% of the time per run. Roughly how many runs do you expect?

About 1 / 0.14 ≈ 7 runs (6 failures and 1 success).

Local search · sometimes go downhill

Simulated annealing

Hill climbing never goes down, so it gets trapped. Simulated annealing sometimes accepts a worse move on purpose, often at first and rarely at the end, to shake itself out of small hills.

Learn it firstabout 5 minutes
1

Where the name comes from

Metalworkers heat metal and cool it slowly so the atoms settle into a strong, low-energy arrangement. Hot: atoms move around wildly. Cold: they barely move. The algorithm copies this with a number called the temperature T.

2

One step

  1. Pick a random neighbour (not the best one).
  2. ΔE = value(neighbour) − value(current).
  3. If ΔE > 0 (better): always move.
  4. If ΔE ≤ 0 (worse): move anyway with probability p = eΔE / T.
  5. Lower T a little (the schedule), and repeat.
3

Work the probability by hand

ΔETp = eΔE/TMeaning
−210e−0.2 = 0.82hot: a small step down is usually taken
−1010e−1 = 0.37a big step down, still often taken
−21e−2 = 0.14cooler: rarely taken
−101e−10 ≈ 0.00005cold: almost never

Two rules come out of the table: bigger drops are less likely, and lower temperature makes every drop less likely.

4

Why it works

Early on, while T is high, it wanders freely and can climb out of local maxima. As T falls it behaves more and more like hill climbing. If T is lowered slowly enough, it finds the global optimum with probability approaching 1.

In one line

Random neighbour; always accept better; accept worse with p = eΔE/T; cool down.

When T → 0

p → 0 for every bad move, so it becomes hill climbing.

Related

Local beam search keeps k states at once and keeps the k best of all their neighbours.

Check yourself
Current value 20, neighbour value 15, T = 5. Probability of moving?

ΔE = 15 − 20 = −5, so p = e−5/5 = e−1 ≈ 0.37.

Neighbour value 25 instead. Probability?

ΔE = +5 > 0, a better move: it is always taken (probability 1).

Anneal the same landscape

Switch between the two methods from the same starting point. Hill climbing stops on the first hill. Annealing shows the probability it computed for every downhill move, and usually ends higher.

CSP · deck 05 slides 2–16

Constraint satisfaction problems

Some problems are not about a route but about filling in values so that rules hold: colour a map, fill a Sudoku, build a timetable. A CSP describes them with three lists, and that structure makes them much faster to solve.

Learn it firstabout 6 minutes
1

Planning vs identification (slide 2)

Search problems so far were planning: the path matters. A CSP is identification: only the final assignment matters, and every complete answer has the same depth (one value per variable).

2

Three lists define every CSP

VariablesX1 … Xn: the things to decide. Map: WA, NT, SA, Q, NSW, V, T.
Domainsthe values each variable may take. Map: {red, green, blue}.
Constraintswhich combinations are allowed. Map: neighbouring regions differ, e.g. WA ≠ NT.

A solution is a complete assignment (every variable has a value) that satisfies every constraint.

3

The constraint graph (slide 10)

Draw one node per variable and an edge for every binary constraint. For the map: WA–NT, WA–SA, NT–SA, NT–Q, SA–Q, SA–NSW, SA–V, Q–NSW, NSW–V. T has no edges: Tasmania is an independent subproblem and can be solved on its own.

4

Kinds of constraints (slide 15)

Unaryone variable: SA ≠ green (just shrink its domain)
Binarytwo variables: SA ≠ WA
Higher-orderthree or more: a cryptarithmetic column
Soft (preferences)red is better than green: a cost, not a rule
5

Kinds of variables (slide 14)

Discrete, finite domains (size d, n variables): dn complete assignments, e.g. Boolean CSPs. Discrete, infinite: integers or strings, like job start times. Continuous: real numbers, like telescope observation times; linear constraints there are solved by linear programming.

In one line

Variables, domains, constraints. Solution = complete and consistent assignment.

Exam habit

“Formulate as a CSP” means write exactly those three headings, then draw the constraint graph.

Formulations to know

N-queens, formulation 1 (slide 7)

Variables: Xij, one per square. Domains: {0, 1}. Constraints: no two 1s in a row, a column or a diagonal, and exactly N ones in total.

N-queens, formulation 2 (slide 8)

Variables: Qk, one per row. Domains: {1, …, N}, the column. Constraints: for every pair i, j: Qi and Qj are not in the same column or diagonal. Smaller and better.

Sudoku (slide 12)

Variables: each open square. Domains: {1, …, 9}. Constraints: 9-way alldiff for each row, each column and each 3×3 region (or many pairwise ≠).

Cryptarithmetic: TWO + TWO = FOUR (slide 11)

Variables: F, T, U, W, R, O and carries C1, C2, C3. Domains: {0, …, 9}; carries {0, 1}. Constraints: alldiff(F, T, U, W, R, O); O + O = R + 10·C1; C1 + W + W = U + 10·C2; C2 + T + T = O + 10·C3; C3 = F; T ≠ 0, F ≠ 0.

Real-world CSPs (slide 16)

Who teaches which class, timetabling, hardware configuration, transport and factory scheduling, circuit layout, fault diagnosis.

CSP · deck 05 slides 18–23

Backtracking search

The basic way to solve a CSP: depth-first search that assigns one variable at a time and refuses any value that breaks a constraint.

Learn it firstabout 5 minutes
1

Plain search is terrible here (slides 18–19)

As a normal search problem: the state is a partial assignment, the start is {} and each action assigns some variable. BFS would build every partial assignment before finishing any. DFS would fill in all variables and only then check the constraints, finding the clash between WA and NT at the very bottom.

2

Two small ideas fix it (slide 21)

Idea 1, one variable at a time: WA = red then NT = green is the same as NT = green then WA = red, so fix an order and only decide one variable per level. Idea 2, check as you go: only try values that don’t clash with what is already assigned (an incremental goal test).

Backtracking = DFS + one variable per level + fail on violation

3

What “backtrack” means

If a variable has no value left that fits, go back to the previous variable and try its next value. That is all. With order NSW, WA, Q, V, SA, NT, T the visualiser below runs into dead ends and backtracks 9 times before it finds a colouring.

4

How to make it faster (slide 24)

Filtering: spot doomed branches early (next page). Ordering: choose which variable and which value to try first (the page after). Structure: split independent parts, like Tasmania.

In one line

DFS over variables, one per level, skip any value that clashes, back up when stuck.

Power

Plain backtracking solves n-queens up to about n = 25 (slide 21).

CSP · deck 05 slides 25–27

Filtering: forward checking and arc consistency

Keep a domain for every unassigned variable and cross off values that can no longer work. When a domain becomes empty, you know this branch is dead before you walk down it.

Learn it firstabout 6 minutes
1

Forward checking (slide 26)

After assigning X = v, go to every unassigned neighbour of X and cross v off its domain. If any domain becomes empty, undo X = v straight away.

AfterWANTSAQNSWV
startRGBRGBRGBRGBRGBRGB
WA = RRGBGBRGBRGBRGB

2

What forward checking misses (slide 27)

Look at the last row: NT and SA both have only blue left, and they are neighbours, so they cannot both be blue. The branch is already dead. Forward checking does not notice, because it only looks from assigned variables to unassigned ones, never between two unassigned ones.

3

Arc consistency: check between unassigned variables too

An arc X → Y is consistent if for every value x left in X there is some value y left in Y that fits the constraint. If x has no partner, delete x from X. Check SA → NT: SA’s only value B needs NT ≠ B, but NT has only B. Delete B from SA: SA is empty, so fail now.

4

AC-3, the bookkeeping

  1. Put arcs in a queue.
  2. Take an arc X → Y and remove the values of X that have no partner in Y.
  3. If X lost a value, add every arc Z → X back to the queue (Z’s values might have depended on the removed one).
  4. Stop when the queue is empty, or a domain is empty (failure).

Remember the direction: when X shrinks, recheck the arcs into X.

In one line

FC: cross off neighbours of what you just assigned. AC: keep crossing off until every value has a partner.

Trade-off

AC catches more dead ends but costs more work per step. FC is cheap and catches many.

Check yourself
Is the arc NT → SA consistent when D(NT) = {B} and D(SA) = {G, B}?

Yes. For NT = B there is SA = G, which satisfies NT ≠ SA. (The reverse arc SA → NT removes B from SA.)

CSP · deck 05 slides 28–30

Ordering: MRV and LCV

Which variable to fill in next, and which value to try first, can turn a long search with many dead ends into a straight run.

Learn it firstabout 4 minutes
1

MRV: minimum remaining values (slide 29)

Choose the variable with the fewest legal values left, the “most constrained variable”. Why the fewest? If something is going to fail, it is most likely this variable, so find out now instead of after building on top of it. This is fail-fast.

2

Breaking MRV ties: the degree heuristic

At the very start every region has 3 values, so MRV ties. Then pick the variable involved in the most constraints with unassigned variables. On the map that is SA (5 neighbours), which is why MRV starts with SA.

3

LCV: least constraining value (slide 30)

Once the variable is chosen, try first the value that rules out the fewest values in the neighbours’ domains. Why the least? You only need one solution, so keep the most options open for everyone else.

4

Remember the asymmetry

Variables: most constrained first (fail fast). Values: least constraining first (succeed fast). Together they make 1000-queens feasible (slide 30).

In one line

MRV picks the variable, LCV orders its values.

Don’t confuse

MRV counts values left in a variable’s own domain. LCV counts values a choice would remove from others.

Same map, smarter order

Turn on MRV with any filtering: the dead ends drop to 0. Turn it off again to compare.

Games · deck 06 slides 2–8

Games: search with an opponent

So far the agent was alone. In a game, every second move is made by someone who wants you to lose. You can no longer plan a path; you need a strategy that works whatever they do.

Learn it firstabout 5 minutes
1

Competitive vs cooperative (slide 2)

With several agents, each must think about what the others will do. When their goals conflict (competitive) we get adversarial search, also called games. Cooperative settings, like taxis sharing a road, are different.

2

The kind of game AI studies (slide 3)

Deterministic, turn-taking, two-player, zero-sum, perfect information, like chess or tic-tac-toe. Zero-sum: one player’s gain is exactly the other’s loss, so the utilities at the end are equal and opposite (+1 and −1).

3

A game as a search problem (slides 6–7)

S0the initial position
PLAYER(s)whose turn it is: MAX or MIN
ACTIONS(s)the legal moves
RESULT(s, a)the position after a move
TERMINAL-TEST(s)is the game over?
UTILITY(s, p)the final score for player p (win, lose, draw)

Together they define the game tree: nodes are positions, edges are moves, and levels alternate MAX, MIN, MAX…

4

MAX and MIN

MAX is us: we want the highest utility. MIN is the opponent: they want the lowest. In drawings MAX nodes point up (△) and MIN nodes point down (▽), exactly as on the deck.

In one line

Two players, alternating moves, one’s win is the other’s loss: search the game tree.

Size

Tic-tac-toe has fewer than 9! = 362,880 terminal nodes. Chess: about 35 moves per position, so the full tree is far too big to search.

Strategy, not a path

A search answer was a sequence of actions. A game answer is a strategy: what MAX should do in reply to every possible move of MIN.

Environment properties

Chess with a clock: fully observable, deterministic, sequential, semidynamic, discrete, multi-agent (competitive). Poker: partially observable and stochastic, so it falls outside this chapter.

Games · deck 06 slides 9–15

Minimax

Assume the opponent plays perfectly. Then the value of a position is what you get if both sides always choose their best move, and you can work it out from the leaves upwards.

Learn it firstabout 5 minutes
1

The rule (slide 10)

MINIMAX(n) = utility if n is terminal; max of the children if MAX moves; min of the children if MIN moves

The minimax value of a node is the utility for MAX of being there, assuming both players play optimally to the end.

2

Work it bottom-up

Textbook tree: MAX at the root, three MIN children A, B, C, each with three leaves: A (3, 12, 8), B (2, 4, 6), C (14, 5, 2).

NodeWho movesValue
AMINmin(3, 12, 8) = 3
BMINmin(2, 4, 6) = 2
CMINmin(14, 5, 2) = 2
rootMAXmax(3, 2, 2) = 3: play A

C has the 14, but MIN would never let MAX have it: MIN would answer with 2.

3

How the algorithm actually runs

It is a depth-first search: it dives to the leftmost leaf, then passes values up as each subtree finishes. Time O(bm), memory O(bm), for branching factor b and depth m.

4

Real games are too deep (slides 12–14)

You cannot reach the leaves of chess. So: search to a depth limit and replace utilities with an evaluation function that estimates how good a position is. With 100 seconds at 10,000 nodes per second you can look at 1 million nodes per move; with alpha-beta that reaches about depth 8. The price: the guarantee of optimal play is gone, because evaluation functions are imperfect.

In one line

Leaves upwards: MAX takes the max, MIN takes the min.

Optimal?

Yes, against an optimal opponent. Against a weaker one it is still safe, never worse.

Step through minimax

How it is asked

Practice (deck slide 43(a))

Practically, it is not possible to run down the depth of the game tree when depth and branching factor are both large. How can the performance of the minimax algorithm be improved? [1]

Worked answer

Cut the search off at a fixed depth and score the positions there with a heuristic evaluation function instead of the true utility, and use alpha-beta pruning (with good move ordering) to skip branches that cannot change the decision.

Games · deck 06 slides 16–42

Alpha-beta pruning

Same answer as minimax, far fewer nodes. Alpha-beta notices when a branch cannot change the final decision and stops exploring it.

Learn it firstabout 8 minutes
1

The intuition with the textbook tree

MAX already knows A is worth 3. Now look at B. Its first leaf is 2, so MIN at B can force a value of 2 or less. MAX will never choose B over A (3 > 2), so B’s other leaves, 4 and 6, don’t matter. Skip them. That skipping is pruning.

2

Two numbers carried down the tree (slide 18)

α (alpha)the best value MAX can already guarantee on the path so far. Starts at −∞, only goes up. Updated at MAX nodes.
β (beta)the best (lowest) value MIN can already guarantee. Starts at +∞, only goes down. Updated at MIN nodes.
3

The two pruning rules

  1. At a MAX node: after each child, v = max(v, child). If v ≥ β, stop and return v. Otherwise α = max(α, v).
  2. At a MIN node: after each child, v = min(v, child). If v ≤ α, stop and return v. Otherwise β = min(β, v).

α and β are passed down to children; values are passed up to parents.

4

The deck’s example (slides 22–41)

MAX root; two MIN children; each has two MAX children; leaves 4 6 | 7 9 | 1 2 | 0 1.

WhereWhat happens

second MAXgets β = 6, sees 7: v = 7 ≥ 6, prune 9. Left MIN keeps 6.
rootα = 6. Right MIN gets α = 6.

5

Move ordering

Pruning works best when the best moves are looked at first. With perfect ordering alpha-beta examines about O(bm/2) nodes instead of O(bm): it can search twice as deep in the same time (slide 17). It never changes the answer, only the work.

In one line

Carry α and β down; prune at MAX when v ≥ β, at MIN when v ≤ α.

Model answers for short theory

What is a rational agent?

For each percept sequence, it selects the action expected to maximise its performance measure, given the percepts and its built-in knowledge.

Rational vs omniscient?

Rational maximises expected performance. Omniscient knows the actual outcome, which is impossible. A rational agent can still be unlucky.

What does rationality depend on?

The performance measure, prior knowledge of the environment, the actions available, and the percept sequence so far.

What is the Turing test?

A computer passes if a human asking written questions cannot tell it from a person. It needs NLP, knowledge representation, automated reasoning and machine learning.

What is a search problem?

A state space, a successor function with actions and costs, a start state and a goal test. A solution is an action sequence from start to goal.

What is the fringe?

The paths generated but not yet expanded. The strategy decides which comes out next.

Complete vs optimal?

Complete: finds a solution if one exists. Optimal: finds the least-cost solution.

Why is DFS not complete?

On an infinite tree or with cycles it can run down one branch forever. Complete only if cycles are prevented.

Why is BFS not always optimal?

It finds the fewest actions, not the lowest cost. Optimal only when every step costs the same.

Admissible vs consistent?

Admissible: h(n) ≤ true cost to the goal. Consistent: h(u) − h(v) ≤ cost(u, v) on every edge. Consistent implies admissible.

The bound (threshold or f_limit) is only meant to decide whether a node is expanded. If the goal test came after the bound check, a goal whose f is above the current bound would be cut off instead of recognised.
The search would then waste work: IDA* would need extra iterations until the threshold reached f(goal), and RBFS would fail and back up from a branch that already contained the goal.
